# problems.md

## Обзор

В этом документе описаны ключевые проблемы, возникающие при трансляции GPMA IR (Go + ACSL-подобные аннотации) в Viper с сохранением семантики и выразительности.

---

## 1. Трансляция управления потоком (Control Flow)

### Проблема

В Viper отсутствуют следующие конструкции:

* `return`
* `break`
* `continue`

### Следствие

Необходимо нормализовать управление потоком перед трансляцией.

### Текущий подход

Наивное отображение:
```
return x <=> res := x
```

некорректно, так как не учитывает:

* ранние выходы
* вложенные конструкции

Примеры некорректной трансляции при таком подходе можно увидеть на примере в файлах 
[clamp.vpr](projects/clamp/clamp.vpr)
[clamp.go](projects/clamp/clamp.go)

### Требуемое решение

Необходимо внедрить преобразование:

* single-exit форма (предпочтительно), либо
* использование флагов управления (`done` и ....)

## 2. Трансляция массивов

### Текущий подход

Используется стандартный encoding из tutorial Viper:
```
domain IArray {
    function slot(a: IArray, i: Int): Ref
    function len(a: IArray): Int
    function first(r: Ref): IArray
    function second(r: Ref): Int
    
    axiom all_diff {
        forall a: IArray, i: Int ::
            { slot(a, i) } first(slot(a, i)) == a
            && second(slot(a, i)) == i
    }
    
    axiom len_nonneg {
        forall a: IArray :: { len(a) } len(a) >= 0
    }
}

field val: Int

define access(a) (forall j: Int ::
    0 <= j && j < len(a) ==> acc(slot(a, j).val))
```
Пример использования такой трансляции:
[forall.vpr](projects/forall/forall.vpr)
[forall.go](projects/forall//forall.go)

### Проблема

Этот подход:

* хорошо работает для чтения
* может быть недостаточен для:

  * изменяемых массивов
  * aliasing
  * частичных permissions

### Открытые вопросы

* Как поддерживать запись (`a[i] = ...`)
* Как обрабатывать aliasing (`a == b`)
* Нужно ли расширять текущую модель

## 3. Ввод из stdin

### Проблема

Go-программы могут зависеть от внешнего ввода:

* `stdin`
* парсинг (`ParseFloat`)
* ветвления по ошибкам

Пример:
[main.vpr](projects/interactive/main.vpr)
[main.go](projects/interactive/main.go)

### Проблема в контексте Viper

Viper не моделирует:

* ввод/вывод
* внешнюю среду

### Требуемое решение

Абстрагировать ввод (недетерминированные значения)

Либо: ограничить поддерживаемое подмножество языка

## 4. Поддержка вещественных чисел

### Проблема

В Viper отсутствует полноценная поддержка `float` или `Rational`.

### Следствие

`float64` из Go нельзя напрямую транслировать.

### Возможные решения

* аппроксимация через `Int`
* введение `domain Float`
* исключение из MVP

### Риск

Потеря точности (rounding, NaN и т.д.)

---

## 5. Покрытие языка Go

### Проблема

Значительная часть языка не поддерживается:

* closures
* сложные структуры данных
* стандартная библиотека
* продвинутый control flow

### Следствие

Необходимо ограничить подмножество языка

---

## 6. Assigns и framing

### Проблема

ACSL использует:

```text
assigns ...
```

Viper использует permissions.

### Проблема

Нет прямого соответствия.

### Решение

Интерпретировать `assigns` как:

* множество изменяемой памяти
* подсказку для генерации `acc(...)`

---

## 7. Циклы (инварианты и варианты)

### Проблема

ACSL предоставляет:

* loop invariant
* loop variant

Viper требует:

* корректные (достаточно сильные) инварианты
* `decreases` для завершения

### Риск

Инварианты могут быть:

* слишком слабыми
* неполными

### Следствие

Верификация может не проходить даже для корректного кода

---

## 8. Основные риски

* несовпадение control flow
* отсутствие модели float
* неполная модель массивов
* отсутствие генерации инвариантов
* отсутствие модели I/O
* mismatch между assigns и permissions
