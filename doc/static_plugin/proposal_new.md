# proposal.md

## Цель

Разработать статический плагин, который:

* транслирует GPMA IR в Viper
* запускает верификацию
* возвращает результаты пользователю

---

## 1. Общий пайплайн

```
Go parser 
          \       |                  Static Plugin                        |
        GPMA IR -> GPMA Preprocessor -> Viper -> Verifier -> Result Mapping
          /
GPMA parser
```



---

## 2. Поддерживаемые конструкции (начальный этап)

Можно поддержать сразу:

* contracts (`requires`, `ensures`)
* assertions
* loop invariants
* loop variants (`decreases`)
* базовый control flow
* скалярные типы (`Int`, `Bool`)

`assigns`:

* не имеет прямого аналога в Viper
* может использоваться как подсказка при генерации Viper кода

---

## 3. Архитектура

### 3.1 Frontend (IR)

* вход: GPMA IR
* задачи:

  * нормализация control flow
  * устранение `return`, `break`, `continue`

---

### 3.2 Specification Mapper

Отображение:

* `requires` → предусловия
* `ensures` → постусловия
* `assert` → assert
* кванторы → `forall`, `exists`

---

### 3.3 Types Mapper

* `int` → `Int`
* `bool` → `Bool`

Массивы:

* `[]int` → `IArray`
* `a[i]` → `slot(a,i).val`
* доступ через `access(a)` (пока только на чтение)
* для доступ на запись нужно придумать Viper domain, который будет позволять это делать

---

### 3.4 Control Flow Generator

* генерация:

  * `if`
  * `while`
* приведение к форме, совместимой с Viper

---

### 3.5 Loop Module

* добавление:

  * invariants
  * decreases

---

### 3.6 Backend

* генерация `.vpr`

---

### 3.7 Runner

Варианты:

* запуск через Viperserver
* запуск (silicon/carbon) из подпроцессов
* настройка среды для Viper инфраструктуры

Зависимости:

* Viper
* Boogie
* Z3

---

### 3.8 Result Mapping

* парсинг результата от Viper
* отображение Viper результата пользователю

---

## 5. План реализации

### 1 — инфраструктура

* выбрать стек
* сделать dummy плагин:

  * отправка захардкоженого мiper-кода на Viper runner 
  * получение результата
  * вывод результата пользователью

---

### 2 — MVP

Поддержка:

* Int, Bool
* простые функции
* контракты
* ассерты
* циклы с готовыми инвариантами

Без:

* I/O
* float
* сложной памяти

---

### Фаза 3 — развитие

* массивы (чтение + запись)
* aliasing
* трансляция ACSL assigns в permissions на Viper

---

### Фаза 4 — расширение

* моделирование вызова функций сторонниз библиотек
* улучшение диагностики
* помощь с инвариантами циклов
* float и более сложные типы
* aliasing

---
