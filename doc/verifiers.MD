# Языки верификации

Данный документ содержит обзор некоторых языков верификации - Dafny, Boogie и Viper, - с точки зрения возможности трансляции исходного кода на Go со спецификациями в язык верификации.

## Dafny

Dafny — это язык программирования с поддержкой формальной верификации, который 
позволяет не только писать программы, но и формально доказывать их корректность 
с помощью встроенных спецификаций. Соответственно, в языке Dafny используются
конструкции и концепции, типичные для императивных языков программирования. 

В частности, система типов в Dafny поддерживает, помимо базовых скалярных типов
и коллекций, типы функций и ссылочные типы: классы, массивы, трейты и 
итераторы (см. пример ниже). Также поддерживаются индуктивные, коиндуктивные
и зависимые типы, но в рамках данного проекта они не актуальны.

```
trait T {}
class A {}
class B extends T {
  const b: B?
  var v: int
  constructor (vv: int) { v := vv; b := null; }
  function toString(): string { "a B" }
  method m(i: int) { var x := new B(0); }
  static method q() {}
}
```

Классы могут реализовывать трейты, а трейты - расширять другие 
трейты. Таким образом, строится иерархия наследования. При этом, все
связи в этой иерархии должны быть явно указаны в коде. Такой подход
расходится с типизацией в Go, где класс может реализовывать интерфейс неявно,
поэтому в этой точке могут возникнуть проблемы с прямой трансляцией.

## Boogie

Boogie — это промежуточный язык верификации, который служит связующим звеном между высокоуровневыми языками (такими как Dafny) и SMT-солверами. Следовательно, система типов и модель исполнения в Boogie устроена таким
образом, чтобы максимально упростить построение SMT-формул.

Система типов в Boogie значительно проще, чем в Dafny. В этой системе присутствуют только скалярные типы, специализации `Map` и конструкторы типов.
Таким образом, семантика ссылочных типов и функций при трансляции исходного
кода со спецификациями в Boogie должна быть релизована вручную. То есть, 
выражена с помощью конструкций, поддерживаемых в Boogie.

В частности, требуется вручную моделировать структуру кучи и указателей,
иерархию наследования, функции высших порядков.

```
class C { int data ; C next ; }
```

Ниже представлены два примера реализации класса `C` в Boogie.

```
type Ref ;
var C .data: [Ref]int ;
var C .next: [Ref]Ref ;
```

```
type Field α;
type HeapType =〈α〉[Ref, Field α]α;
var Heap: HeapType;
```

Поэтому основная проблема трансляции в Boogie связана с реализацией семантики
языка программирования в семантике Boogie. Кроме непосредственно реализации,
здесь требуется гарантировать корректность, так как ошибки в этом компоненте
сложны для обнаружения и могут привести к ошибкам при верификации.

## Viper

Viper — это инфраструктура для формальной верификации программ, которая предоставляет промежуточный язык верификации и набор инструментов, позволяющих верифицировать поведение программы с помощью дедуктивной верификации или
символьного исполнения.

В отличие от более высокоуровневых языков, Viper ориентирован на явное моделирование состояния кучи и доступа к памяти. Viper поддерживает
встроенную модель кучи, основанную на separation logic. 

Viper поддерживает два варианта верификации. Первый вариант предполагает символьное исполнение, а второй - генерацию кода на Boogie. Таким образом,
поскольку Viper поддерживвает ряд абстракций более высокого уровня, чем
Boogie, трансляция представляет собой реализацию соответствующей семантики. 

При этом, система типов в Viper схожа с системой типов в Boogie. Поэтому реализацию некоторых особенностей системы типов Go при трансляции нужно
будет реализовать вручную.

Существует проект `gobra`, где реализован верификатор программ на Go на
базе инфраструктуры Viper. Значит, можно использовать уже существующую
реализацию трансляции в случае необходимости.
